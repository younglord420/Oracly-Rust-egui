# Tugas DeepSeek: OpineRust editor samping chart dan bridge Pine Script® berbasis Rust

**Status: PROTOTIPE; milestone pertama BELUM selesai / belum aman untuk digunakan mengambil keputusan trading.** Dokumen ini terpisah dari redesign settings study. **OpineRust** adalah nama produk/fitur milik Oracly; runtime fork berasal dari [Pinecone](https://github.com/ferranbt/pinecone). Jangan menyebut seluruh Pine v6 didukung hanya karena `//@version=6` dikenali.

> **Penting — diagnosis historis, bukan status source saat ini.** Bagian §0 dan pernyataan kondisi awal di §7 merekam pemeriksaan prototipe terdahulu. Sejak itu implementasi berubah: misalnya filter kini berbasis token, nilai/warna menggunakan snapshot bersama, dan panel memiliki jalur rail. Itu **tidak** dengan sendirinya membuktikan fitur tersebut sudah benar atau milestone selesai. Jangan mengulangi klaim diagnosis lama sebagai fakta terkini, dan jangan menandai P0–P5 selesai hanya karena perubahan atau tes lama ada.
>
> Untuk status dan prioritas terbaru, baca [`opinerust-status.md`](opinerust-status.md) dan [`opinerust-runtime-fork-v6-roadmap.md`](opinerust-runtime-fork-v6-roadmap.md) seluruhnya, lalu cocokkan dengan source, `git status`/diff dan tes aktual. Secara khusus, audit status error melalui `ConfiguredStudy`, kegagalan kalkulasi saat Run/replace, konteks simbol/timeframe yang tertahan, serta pemetaan interval yang salah. **Spesifikasi produk, batas lisensi, kriteria penerimaan P0–P5, dan definition of done dalam dokumen ini tetap berlaku**; jika deskripsi kondisi awal bertentangan, gunakan source dan status terbaru, bukan tebakan.

## 0. Koreksi status historis: apa yang dilaporkan dan apa yang saat itu masih kurang

**Yang terbukti terbatas:** tes sebelumnya melaporkan 17 tes bridge, 6 tes panel, 82 tes demo, dan 1180 tes library lulus; probe Node/WASM terdahulu memanggil `opinerust::execute` aktual untuk contoh v5/v6 dan `timenow`. Source kini memakai `per_bar(...)` berbasis jam host untuk sema, tidak lagi pemanggilan upstream `per_bar_variables` yang memicu panic `SystemTime::now()` di WASM. Ini kemajuan, **bukan** bukti Run UI browser, data live lengkap, atau runtime yang aman untuk semua script. Jangan klaim suite/tes itu dijalankan kembali pada revisi dokumen ini.

**Masalah yang dilaporkan pada pemeriksaan terdahulu — reproduksi ulang pada source aktual sebelum menentukan apa yang masih terbuka:**

1. **Nilai dan warna live belum sinkron.** `opinerust/src/study.rs::study_from_output` menghitung nilai baru lewat `execute` saat menerima bar, tetapi `plot_color` tetap membaca `Arc` warna dari Run awal; candle baru atau historis yang diperbaiki bisa mendapat warna lama/salah. `rows_from` mengabaikan `last_run` (`let _ = last_run`) dan memakai urutan output baru, bukan mencocokkan identitas plot dengan deklarasi awal. `Err(_)` di recalculation menjadi gap tanpa menyampaikan error. Nilai hasil tes tambah satu candle saja tidak cukup untuk menyatakan P1 selesai.
2. **Identitas `(title, occurrence)` tidak cukup untuk semua kasus.** Jika plot bertitel sama muncul/hilang pada bar berbeda, occurrence-nya bisa berubah; `engine.rs` menambah nilai plot yang baru muncul sebelum melakukan `resize(seen, None)`, sehingga untuk plot pertama muncul pada bar terlambat nilai tersebut berisiko ditempatkan di awal, bukan pada bar yang benar. Uji identitas, padding awal/tengah/akhir, output semua `na`, judul kosong/duplikat, dan perubahan urutan; bila upstream tidak menyediakan identitas yang stabil, tolak pola ambigu dengan diagnostik, bukan tebak.
3. **Filter fitur unsupported masih raw text.** `unsupported_constructs` memotong setiap baris di `//` lalu mencari substring; ia dapat salah menolak teks di string/komentar, melewatkan spasi/newline/alias, dan belum mencakup seluruh output yang tidak dimapping seperti `line.*`, `fill`, `bgcolor`, `barcolor`, `plotchar`, atau `plotcandle`. Pengguna tidak boleh mendapat status sukses jika output penting silently hilang. Gunakan lexer/AST atau mekanisme kapabilitas upstream yang terbukti, dengan negative/positive tests, bukan daftar substring yang rapuh.
4. **Replace belum atomic/aman terbukti.** `examples/demo/controller.rs::show_opinerust` masih `remove_series(previous)` lalu `add_indicator`; ID berubah, dan jalur pengujian sebelumnya menyimulasikan langkah itu alih-alih menguji seluruh handler host, rollback, study limit, pane atau undo/redo. `prepare` masih memanggil `self.editor.apply_result(Ok(()))` **sebelum** chart mengonfirmasi install, walau `confirm_installed` menulis status panel kemudian. Risiko kehilangan study/Applied palsu tidak boleh dianggap selesai.
5. **Panel belum sesuai brief.** Entry hanya command palette; `StudyEditor` tetap menampilkan Apply/Open/Save meski host tak menangani Open/Save. `line_span` memperlakukan nomor baris sebagai offset byte, dan Logs ditempatkan setelah editor yang meminta hampir seluruh tinggi. Belum ada bukti visual/keyboard nyata; tidak boleh menyatakan panel selesai berdasarkan HTTP 200.
6. **Semantik dan kompatibilitas belum lengkap:** interpreter dieksekusi full replay sinkron; tidak ada cancellation/budget/generation guard; syminfo/timeframe nyata dan barstate forming/live belum dipetakan; `input.*` belum menjadi schema settings; warna/style plot dan error saat update belum tervalidasi end-to-end. Penerimaan marker v6 tidak membuktikan seluruh v6. Cargo `"0.2.6"` adalah rentang kompatibel, bukan exact pin; cek lockfile/dependency tree serta atribusi MPL.
7. **WASM/visual/bundle:** probe Node sebelumnya berguna untuk jalur dasar; harus menjadi tes yang repeatable di repo dan ditambah jalur demo/browser aktual. Setelah perubahan apa pun, cocokkan log build dan hash bundle yang benar-benar disajikan, lalu jalankan script di UI dan amati console/chart. HTTP 200 dan string dalam bundle bukan verifikasi runtime.

**Tugas DeepSeek:** jalankan ulang baseline, reproduksi setiap masalah tersebut, perbaiki sesuai prioritas §7, dan laporkan bukti serta hal yang belum lulus. Jangan menyebut P0–P3 atau milestone selesai hanya karena tes yang ada hijau. `git status`/diff harus diperiksa sebelum edit agar perubahan lokal lain tidak tertimpa.

## 1. Keputusan produk dan batasan

- Pengalaman editor mengambil **pola tata letak**, bukan kode, dari [editor Pine pada Vela](https://vela.luxalgo.com/chart/izznntrt02uh3lxdffr5cilv): panel kanan di samping/di atas area chart yang masih terlihat, sekitar 500 px pada desktop, pegangan resize di tepi kiri, header ringkas berisi judul script, Run, aksi dokumen, maximize, dan close; editor mengisi badan panel; Logs/diagnostik dapat dilipat di bawah. Pengamatan dilakukan pada viewport sekitar 1320×906; panel sekitar 509 px, resizer sekitar 7 px. **Jangan meniru ukuran sebagai angka mutlak.** Pada desktop panel boleh overlay bagian kanan chart seperti Vela, tetapi kontrol chart yang tertutup harus tetap dapat diakses setelah panel ditutup atau di-resize. Saat panel ditutup chart kembali penuh. Pada layar sempit gunakan panel yang hampir/full screen atau tata letak adaptif; jangan mengecilkan chart dan editor hingga keduanya tidak bisa dipakai.
- Tindakan Run/Apply **bukan live edit per ketikan**: teks yang sedang diketik tidak mengubah study sampai berhasil diperiksa dan dieksekusi. Error tidak menghapus indikator yang sedang tampil. Save/Open adalah operasi dokumen milik host, **terpisah** dari Run; Save tidak menjalankan script dan Run tidak otomatis menyimpan. Jangan klaim autosave bila tidak ada implementasi persistence.
- Tidak ada jaringan/CDN yang diam-diam dipakai interpreter untuk data utama. Chart/host menyediakan OHLCV, simbol, timeframe dan sumber tambahan secara eksplisit. Runtime tidak boleh mengunduh data sendiri dari Binance/Yahoo jika host tidak memilihnya.
- Dukungan pertama = **indikator Pine dengan output plot**, bukan strategi, broker, alerts, `request.security`, gambar/label/tabel, atau seluruh v6. Kecuali yang benar-benar dipetakan dan diuji, UI harus memberi diagnostik *belum didukung* alih-alih diam-diam mengabaikan output.
- Target penggunaan browser demo: **WASM harus diuji**, bukan diasumsikan bekerja hanya karena Pinecone ditulis dalam Rust. Jika dependensi/runtime tidak dapat berjalan di `wasm32-unknown-unknown`, simpan panel/editor dan desain bridge terpisah, lalu usulkan jalur worker/server Rust dengan keputusan deployment dan privasi yang eksplisit; jangan mengganti Pinecone dengan PineTS tanpa persetujuan.

## 2. Referensi faktual dan koreksi versi

- [Pinecone](https://github.com/ferranbt/pinecone) adalah runtime Rust berlisensi **MPL-2.0**. Manifest workspace `main` saat brief ini ditulis menyebut `pine-lang` **0.2.6**; README masih mencontohkan `0.1`. Pin versi/commit aktual yang diuji; jangan menyimpulkan API dari README lama. [`ScriptBuilder`, `analyze`, `decode_metadata`, `with_data`, `with_inputs`, `with_request_provider`](https://github.com/ferranbt/pinecone/blob/main/crates/pine/src/lib.rs) merupakan titik awal, tetapi konfirmasi tanda tangan API pada versi yang dipilih.
- **Koreksi penting:** [sumber `PineVersion` di `main`](https://github.com/ferranbt/pinecone/blob/main/crates/pine-core/src/version.rs) telah mengenali **V3/V4/V5/V6**, `LATEST = V6`. README yang menyebut hanya v4/v5 tertinggal. Ini membuktikan *pengenalan versi*, **bukan** kesetaraan fungsi v6 dengan TradingView. Jalankan script v6 yang konkret untuk setiap klaim fitur; unsupported syntax/semantics harus menghasilkan lokasi dan alasan error, tidak di-downgrade secara diam-diam ke v5.
- [Pinecone `Data`/`Ohlcv`](https://github.com/ferranbt/pinecone/blob/main/crates/pine-core/src/bar.rs): bar tertua ke terbaru, waktu UNIX **milidetik**, OHLCV, indeks dan flag barstate. `Data::from_ohlcv` menandai seluruh bar sebagai history/confirmed; **jangan gunakan default tersebut untuk bar forming/live** tanpa menguji dan memasok flag yang benar. `with_syminfo`/`with_timeframe` harus mencerminkan instrument dan timeframe chart, bukan nilai palsu.
- [Pinecone `RunResult`](https://github.com/ferranbt/pinecone/blob/main/crates/pine/src/run.rs) menyusun nilai plot menurut **judul** ke `BTreeMap` dan `None` saat `na`, tetapi tidak mencakup semua warna per bar, urutan deklarasi, drawables, atau metadata gaya yang dibutuhkan chart. Jangan jadikan urutan alfabet `BTreeMap` sebagai indeks plot tetap. Audit [`PineOutput`/`PlotOutput`/`InputOutput`](https://github.com/ferranbt/pinecone/blob/main/crates/pine-core/src/output.rs) dan output **per bar**; tentukan identitas output yang stabil (mis. indeks deklarasi + judul) dan bagaimana metadata `plot()` yang dinamis disimpan.
- [Vela-pinets](https://github.com/LuxAlgo/Vela-pinets) adalah **referensi arsitektur/perilaku v5/v6**, bukan dependensi tugas ini. Pelajari pemisahan engine lewat port, worker untuk beban berat, metadata input/props, per-bar plot/warna/drawing, dan penanganan error. Runtime-nya PineTS/TypeScript dan dependensinya AGPL-3.0; **jangan impor, tempel, atau transliterasi kode** ke bridge MPL/Rust. Vela core dan addon adalah produk berbeda; dukungan fitur di Vela-pinets tidak otomatis ada di Pinecone.
- Pine Script® adalah merek TradingView; jangan menyiratkan kompatibilitas/afiliasi resmi. Lakukan review lisensi dan NOTICE saat mendistribusikan Pinecone atau modifikasinya (MPL-2.0), termasuk bundling WASM; catat versi, lisensi, sumber, dan kewajiban distribusi. Ini bukan nasihat hukum final.

## 5. Kontrak bridge Rust yang perlu dibuktikan

**Fase awal: `indicator(...)` dengan dua `plot(...)`, v5 dan satu script v6 ekuivalen yang benar-benar lolos.** Bentuk paket data konseptual (bukan signature wajib): source + input overrides + identitas simbol/timeframe/instrument + OHLCV oldest-first + id/generation → compile/execute result berupa status, diagnostik terstruktur, metadata deklarasi, daftar plot dalam urutan tetap, nilai per bar termasuk gap `na`, warna/gaya yang benar-benar dipetakan, dan daftar fitur yang ditolak. Pastikan kepemilikan dan thread boundary eksplisit.

- Input OHLCV: konversi `Bar.time` ke UNIX milidetik tanpa overflow, pertahankan high/low/open/close/volume, urutan waktu, jumlah bar dan timestamp; jangan kirim whitespace/invalid non-finite seolah bar valid. Tentukan kebijakan chart bar terakhir sedang forming, replay, dan perubahan simbol/timeframe; barstate tidak boleh salah. `Pinecone::Data` harus memakai metadata instrument/chart yang nyata atau menyatakan field `syminfo.*` belum didukung bila metadata tidak lengkap. Tidak ada hidden lookahead pada HTF di tahap berikutnya.
- Eksekusi: tentukan `pine-lang` versi/commit terpin. Uji `analyze`/diagnostics, `decode_metadata`/input, `ScriptBuilder::with_data(...)`, `compile`, lalu `run`; amati kebutuhan data untuk compile (jangan klaim compile tanpa data bila API tidak mendukung). Hasil eksekusi harus dibandingkan dengan fixture angka yang diketahui. Audit apakah `run()`/`run_fn` memberi identitas plot deklarasi, warna per bar, style, `overlay`, `input.*`; bila hanya `RunResult` tersedia, **jangan** diam-diam menghilangkan warna atau mengganti urutan plot berdasarkan judul. Batasi scope MVP secara eksplisit jika warna dinamis/fill belum bisa dipetakan.
- Output: urutan bar dan plot stabil, `na`→`IndicatorValue::None`/NaN tanpa menyambung garis melewati gap; `IndicatorValue::Multiple` untuk dua line, `line_count`/`line_names` cocok, `is_overlay` mengikuti deklarasi (atau penempatan host yang sah), warna dasar/warna per bar tidak tertukar. Jangan menjanjikan drawing, bgcolor, fill atau strategy marker hanya karena output Pinecone memiliki tipenya; tiap tipe perlu adaptor render/test tersendiri. Status Error dapat membawa lokasi (lexer/parser) atau diagnostic sema; ubah ke byte span yang valid UTF-8; runtime error tanpa posisi diberi pesan di Logs, bukan lokasi palsu.
- Apply atomik: kalkulasi kandidat **sebelum** chart lama disentuh. Bila gagal di lex/parse/sema/runtime, jumlah study, `SeriesId`, pane, tampilan, input/palette, history/undo dan source editor tetap seperti semula. Bila sukses, tambah/replace dalam **satu user action**; untuk versi pertama boleh memilih “Add new” saja bila replace tidak dapat menjaga id/penempatan—UI harus menamai aksi dengan jujur dan tes terhadap duplikasi. Jangan menggunakan urutan `remove_series` lalu `add_indicator` tanpa strategi rollback ketika proses tambah menghitung/menolak kandidat.
- Perubahan input, bar live, chart symbol/timeframe, replay, dan resize: definisikan invalidasi dan cache. MVP boleh melakukan full replay setelah Run dan pada update data bila beban dibatasi, namun ukur CPU/memori untuk sejarah panjang; pastikan tidak ada interpreter state lama bocor ketika script diulang. Sebelum produksi, buat rencana incremental update/bar forming dan cancellation; jangan lakukan full replay pada tiap repaint egui tanpa batas.
- `request.security` dan library imports ditunda hingga host punya resolver bar history/library yang jelas (termasuk kegagalan unavailable data dan siklus); begitu juga alerts, tables, drawings dan strategi. Saat script memakainya, terbitkan pesan **fitur belum didukung** yang spesifik; jangan tampilkan plot kosong sebagai sukses.

## 6. Fase v6, matriks kapabilitas dan perbandingan referensi

- Simpan **matriks perilaku** per fitur pada laporan DeepSeek: script fixture minimal, target v5/v6, hasil Pinecone (compile/run/output), hasil referensi yang dapat dibandingkan, status `supported` / `partial` / `unsupported`, alasan, test native dan WASM. Pengakuan `PineVersion::V6` saja = *version marker dikenali*, bukan “Pine v6 lengkap”. Jangan mengklaim cocok dengan Vela hanya dari teks README; [Vela-pinets](https://github.com/LuxAlgo/Vela-pinets) dapat dipelajari untuk kontrak engine/worker/props/trades tetapi bukan oracle mutlak per hitungan tanpa fixture.
- Urutan peningkatan setelah MVP: (a) input `int`/`float`/`bool`/`source`/`color`, nilai default dan validation; (b) styling, warna dinamis, fill, plot mode dan gap; (c) perubahan candle live dan `barstate`; (d) `request.security`/MTF/host data; (e) deklarasi v6 yang semantik atau builtinnya berbeda; (f) drawings/tables/alerts; (g) strategi/broker/report. Setiap gelombang menambah fixture regresi v5+v6, error negasi, dan uji native+WASM sebelum status di UI dinaikkan.
- Kalau script `//@version=6` menggunakan subset yang lulus, **boleh** berjalan dan ditandai “v6 subset didukung”; jika meminta fitur belum ada, tolak dengan error spesifik, **jangan menurunkan versi secara diam-diam**. Untuk script tanpa anotasi, pilih kebijakan default yang jelas; Pinecone `LATEST=V6` tetapi dokumentasinya sendiri menyebut Pine tradisional mengasumsikan v1, sehingga pilihan host harus eksplisit dan diuji.

## 7. Prioritas implementasi DeepSeek dan gerbang penerimaan

**Kondisi awal historis:** butir-butir di bawah disusun terhadap revisi prototipe terdahulu; rincian seperti nama fungsi, snapshot warna, filter, alur tombol, atau versi pin mungkin sudah berubah. Baca penanda di awal dokumen dan roadmap/status terbaru terlebih dahulu, lalu reproduksi terhadap source aktual. Gerbang penerimaan dan urutan prioritas tetap wajib. Ikuti workflow CBM §3, periksa `git status`/diff, baca source yang flagged stale/not-tracked, dan jalankan baseline yang relevan. Jangan overwrite kode dan lockfile yang sudah ada. Untuk fungsi baru yang tidak terindeks, catat gap CBM, periksa pemanggil lewat source; reindex jika tersedia dan aman, lalu trace inbound sebelum edit. Jangan mengulang langkah UI yang menutupi bug data.

### P0 — Jalur runtime WASM aktual, bukan hanya spike

- Ganti juga pemanggilan `pine_builtins::per_bar_variables` pada fase sema `execute`; pastikan **seluruh** jalur lex/parse/sema/execute aman untuk `wasm32-unknown-unknown`, termasuk build error dan script yang memakai `timenow`/`barstate`. Jam berasal dari host yang jelas, bukan wall clock palsu. Bandingkan `per_bar` lokal terhadap versi upstream yang tepat agar semantik tetap selaras; kunci dependensi dengan versi/lockfile yang benar dan audit atribusi MPL untuk kode turunan. Jangan meng-copy lebih banyak kode upstream tanpa meninjau kewajiban lisensi.
- Tambahkan tes `wasm-bindgen-test` atau harness browser yang menjalankan **public `opinerust::execute`/`build_study` sebenarnya** dengan v5 dua plot, v6 subset dan error semantik, termasuk `timenow`. Jalankan tes itu di browser/WASM; `cargo check --target ...`, spike terpisah, marker string dan HTTP 200 **tidak cukup**. Catat command, target browser/Node, dan hasil. Jika toolchain/browser tidak tersedia, laporkan blocker; jangan klaim Run aman.

### P1 — Hasil mengikuti data chart dan tetap selaras

- Source saat ini sudah menghitung ulang nilai dari bar, tetapi **warna per bar dan identitas output masih snapshot Run awal**. Ganti dengan satu snapshot hasil berpasangan (nilai + warna + metadata + revision) yang dipublikasikan atomik dan memenuhi `Indicator: Send` tanpa `unsafe impl Send`; `plot_color` harus membaca warna dari snapshot revision yang sama dengan `values`. Pastikan clone/history tidak berbagi state mutable secara tidak sengaja. Jika memakai worker/thread/worker browser, kirim owned `Send` data dan abaikan hasil job lama. Jangan compile/replay setiap frame. Pertahankan source, overrides, symbol/timeframe, metadata dan versi yang dapat direkonstruksi; batasi waktu/memori dan ukur dampak full replay. Bila belum ada cara menghentikan script tanpa membekukan UI, laporkan blocker; full replay sinkron hanya prototipe terbatas, **bukan** bukti responsivitas produksi.
- Integrasi harus diuji secara numerik: candle baru di-append, candle terakhir diperbarui berulang, bar historis dikoreksi/prepend, chart symbol/timeframe diganti, replay maju/mundur dan input script berubah. Bandingkan output dengan full replay fixture terbaru, termasuk urutan timestamp, panjang array dan indeks asli. Jangan menghapus bar whitespace/non-finite lalu menggeser nilai yang diplot; pilih strategi gap atau menolak dataset dengan error jelas. Tetapkan cara barstate forming/history dan syminfo/timeframe tersedia—jangan melabel semua real-time bar sebagai historical confirmed.
- Saat terjadi update async, sertakan revision data + revision script + identitas chart dalam job; hasil lama yang datang belakangan harus diabaikan. Error ketika update live tidak boleh diam-diam menampilkan hasil lama sebagai data terbaru: tampilkan status stale/error dan kebijakan mempertahankan hasil sebelumnya yang jelas.

### P2 — Run/replace benar-benar atomik dan dapat di-undo

- Run pertama menambahkan satu study; Run sukses berikutnya untuk dokumen/study yang sama **mengganti** hasilnya, bukan menambahkan duplikat. Preflight compile + execute kandidat dulu; hanya publish setelah chart menerima hasil. Jalur yang sekarang `remove_series` → `add_indicator` **belum** membuktikan rollback dan mengubah `SeriesId`: audit registry, `ConfiguredStudy`, history, pane dan penolakan study limit sebelum memutuskan cara replace; buat seam atomic yang teruji atau laporkan blocker. Pertahankan identity/placement/style/input bila sesuai kontrak yang dinyatakan; bila ada perubahan yang tak dapat dipertahankan, beri tahu pengguna dan dokumentasikan, jangan diam-diam menyebutnya atomic.
- Uji urutan: Run sukses A → sukses B → gagal C. Setelah B jumlah study tetap satu dan B terlihat; setelah C A/B yang aktif, id/placement/settings dan undo history yang sah tetap utuh; undo/redo sukses bekerja sebagai satu user action. Cakup study limit/rejection, study dihapus oleh pengguna, pane berubah, perubahan chart saat compile dan kegagalan update. Jangan menampilkan `Applied` sampai host mengonfirmasi sukses.

### P3 — Pemetaan output dan penolakan fitur yang belum didukung

- Ganti identitas `(title, occurrence)` dengan identitas deklarasi/output yang stabil dan diuji; judul duplikat dan judul kosong tidak boleh merge atau bertukar tempat ketika satu output tidak muncul. Di `rows_from`, cocokkan hasil baru ke **urutan deklarasi asli**, jangan hanya iterasi urutan yang kebetulan dihasilkan runtime. Pad output baru dengan `None` untuk **semua bar sebelumnya sebelum** push nilai bar saat ini; per output yang hilang, sisipkan `None` tepat di bar itu. Semua-`na` tetap mempertahankan deklarasi bila representasi memungkinkan. Buat fixture yang secara spesifik membuktikan plot baru pada bar ke-3 tidak muncul di bar ke-1, lalu satu output hilang di tengah. Jika upstream tidak memberi identitas stabil untuk kasus tertentu, **tolak kasus itu secara eksplisit**; jangan menghasilkan data salah dengan diam-diam.
- Map opacity Pine `Color.t` 0–100 ke alpha dengan benar; uji warna per bar **setelah** candle append/update/historical prepend, `na` warna, plot style, width, overlay/pane, index/gaps dan multiple plots. Jangan mengklaim semua style didukung jika adaptor selalu memaksa Line. Unsupported `request.security`, imports, strategy, fill/drawings/alerts/tables, input atau style yang belum punya adaptor harus menghasilkan diagnostik yang bisa dipahami **sebelum commit kandidat**, bukan hanya output kosong/berbeda dengan status sukses.
- Gantikan pemindai `unsupported_constructs` berbasis substring dengan analisis syntax/AST atau mekanisme kemampuan yang mempertimbangkan komentar, string, spasi, baris baru dan aliases. Tes positif untuk setiap construct yang belum didukung serta negatif: teks `strategy(` dalam string atau komentar tidak boleh ditolak; variasi sintaks yang sah tidak boleh lolos hanya karena spasi berbeda; jalur output yang hanya terdeteksi saat runtime tetap gagal aman sebelum kandidat dipublish. Jika interpreter/AST tidak menyediakan informasi cukup, blokir subset ambigu dengan pesan jujur dan catat gap.
- Hubungkan metadata `input.*` ke `StudyInput` jika benar-benar dapat round-trip default, jenis/range dan override; jika belum, tampilkan error jelas untuk input yang dapat menghasilkan perilaku salah. Simpan matriks v5/v6 §6 berdasarkan fixture nyata: status supported/partial/unsupported per fitur, hasil native dan WASM. Penanda versi v6 bukan jaminan semantik v6 lengkap.

### P4 — Editor yang jujur dan benar-benar dapat dipakai

- Ikuti panel kanan Vela/§4: entry **OpineRust** di rail kanan (bisa tetap tersedia di command palette), panel resizable/close, Run yang jelas, Logs dan diagnostik. Jangan mengorbankan panel lain: sesuaikan pengujian layout sebelumnya secara sengaja untuk membedakan widget sampel tersembunyi dari entry produk baru; tes reachability desktop/mobile, active state dan toggle.
- Pisahkan Run dari Save: jangan panggil `mark_saved` jika tidak ada penyimpanan yang berhasil. Implementasikan Open/Save di host dengan perilaku native/WASM dan izin yang nyata, atau sembunyikan/nonaktifkan secara jelas sampai tersedia. Pindahkan `StudyEditor::apply_result(Ok(()))` dari `prepare` ke setelah konfirmasi install; skenario kegagalan chart tidak boleh menunjukkan Applied. Jangan hilangkan draft saat panel ditutup. Konversi diagnostik line/column ke byte span pada **source aktual** secara benar untuk UTF-8, CRLF, last line dan indeks out-of-range; error tanpa lokasi tidak diberi span palsu. Logs harus benar-benar muat di panel, tidak terdesak oleh editor yang memakai seluruh tinggi.
- Tes bahwa teks di editor tidak memicu shortcut chart, error bisa diklik dan memilih lokasi yang benar, Run tidak mengubah unsaved state, close/reopen mempertahankan draft, serta error update/unsupported tidak memunculkan status Applied palsu.

### P5 — Build, tes dan verifikasi nyata sebelum handoff

1. Jalankan formatter, lint, tes bridge native + **tes bridge aktual di WASM**, tes chart/replay/undo, editor/host, lalu suite terkait. Laporkan command, jumlah lulus/gagal dan keterbatasan; jangan menganggap exit pipeline `| tail` membuktikan tes berhasil tanpa `pipefail`.
2. Build ulang demo setelah perubahan terakhir; periksa log sukses serta hash/mtime WASM yang disajikan server sesuai build. Jangan menghentikan proses pengguna atau menghapus cache/lock tanpa kebutuhan dan konfirmasi. HTTP 200 bukan bukti runtime.
3. Jalankan di browser: buka panel dari rail, Run script v5 dua plot, Run ulang sukses, Run script error, dan uji v6 subset + unsupported. Verifikasi chart real (overlay/pane, warna/gap), logs dan tidak ada panic console; lanjutkan dengan update candle/symbol/timeframe/replay bila tersedia. Ambil screenshot relevan light/dark dan viewport desktop + sempit. Bedakan review visual nyata dari DOM snapshot kosong/kanvas tidak terbaca.
4. Laporkan tepat apa yang selesai/belum, bug atau gap v6, hasil tes aktual, sumber/versi Pinecone, lisensi dan keputusan produk yang dibutuhkan. Jangan klaim milestone selesai jika browser Run, update data chart, atomic replace atau visual belum terbukti.

**Definition of done milestone pertama:** panel kanan **OpineRust** resizable dan dapat ditemukan dari rail; script indikator v5 dua plot + satu subset v6 berjalan melalui bridge aktual di native **dan browser/WASM** dengan nilai, nama, warna/opacity, gap/urutan benar; chart mengikuti perubahan bar dan konteks tanpa stale output; Run ulang mengganti tanpa duplikasi dan Run gagal mempertahankan study/history; unsupported menghasilkan diagnostik jelas; Open/Save dan unsaved state tidak menipu; visual serta keyboard teruji. Semua kemampuan yang belum ada dinyatakan secara jujur. Jika satu gerbang belum terpenuhi, status tetap **prototipe / belum selesai** dan blocker dilaporkan.
