# Tugas DeepSeek: OpineRust editor samping chart dan bridge Pine Script® berbasis Rust

**Status: spesifikasi saja; belum diimplementasikan.** Dokumen ini terpisah dari redesign settings study. **OpineRust** adalah nama produk/fitur milik Oracly yang dilihat pengguna untuk editor, proses Run, diagnostik, dan indikator hasil script. Implementasi awal menggunakan [Pinecone](https://github.com/ferranbt/pinecone) (`pine-lang`) sebagai **dependensi runtime Rust di balik layar**; Pinecone bukan nama produk kita. Mulai dengan integrasi kecil yang benar-benar berfungsi, lalu naikkan cakupan v6 secara terukur. Jangan menyebut seluruh Pine v6 didukung hanya karena `//@version=6` dikenali.

### Kontrak penamaan dan atribusi

- UI, navigasi, header panel, pesan status, log operasional, fitur pada dokumentasi pengguna, dan identitas integrasi host yang kita miliki bernama **OpineRust**: gunakan “OpineRust” atau “OpineRust Editor” secara konsisten. Tombol aksi cukup **Run**; tidak perlu “Run with Pinecone”. Istilah **Pine Script®** tetap dipakai untuk nama bahasanya, bukan nama produk. Jangan mengklaim OpineRust adalah implementasi/produk resmi TradingView.
- Nama teknis upstream **Pinecone**, crate **`pine-lang`**, modul, API, versi, dan lisensi **MPL-2.0** tetap dicantumkan apa adanya dalam dokumen developer, manifest dependensi, atribusi/NOTICE, serta catatan distribusi dan audit lisensi. Jangan mengganti nama crate eksternal menjadi `OpineRust` dalam instruksi build atau menyembunyikan asal dependensi. Jika membuat crate/adaptor milik kita, nama internal seperti `opinerust` masuk akal; pilih nama yang tidak bentrok setelah memeriksa struktur workspace.
- [Vela](https://vela.luxalgo.com/chart/izznntrt02uh3lxdffr5cilv) dan [Vela-pinets](https://github.com/LuxAlgo/Vela-pinets) hanya referensi tata letak dan perilaku. Jangan memunculkan merek mereka sebagai nama editor kita atau menganggap addon AGPL mereka bagian dari OpineRust.

## 1. Keputusan produk dan batasan

- Pengalaman editor mengambil **pola tata letak**, bukan kode, dari [editor Pine pada Vela](https://vela.luxalgo.com/chart/izznntrt02uh3lxdffr5cilv): panel kanan di samping/di atas area chart yang masih terlihat, sekitar 500 px pada desktop, pegangan resize di tepi kiri, header ringkas berisi judul script, Run, aksi dokumen, maximize, dan close; editor mengisi badan panel; Logs/diagnostik dapat dilipat di bawah. Pengamatan dilakukan pada viewport sekitar 1320×906; panel sekitar 509 px, resizer sekitar 7 px. **Jangan meniru ukuran sebagai angka mutlak.** Pada desktop panel boleh overlay bagian kanan chart seperti Vela, tetapi kontrol chart yang tertutup harus tetap dapat diakses setelah panel ditutup atau di-resize. Saat panel ditutup chart kembali penuh. Pada layar sempit gunakan panel yang hampir/full screen atau tata letak adaptif; jangan mengecilkan chart dan editor hingga keduanya tidak bisa dipakai.
- Tindakan Run/Apply **bukan live edit per ketikan**: teks yang sedang diketik tidak mengubah study sampai berhasil diperiksa dan dieksekusi. Error tidak menghapus indikator yang sedang tampil. Save/Open adalah operasi dokumen milik host, **terpisah** dari Run; Save tidak menjalankan script dan Run tidak otomatis menyimpan. Jangan klaim autosave bila tidak ada implementasi persistence.
- Tidak ada jaringan/CDN yang diam-diam dipakai interpreter untuk data utama. Chart/host menyediakan OHLCV, simbol, timeframe dan sumber tambahan secara eksplisit. Runtime tidak boleh mengunduh data sendiri dari Binance/Yahoo jika host tidak memilihnya.
- Dukungan pertama = **indikator Pine dengan output plot**, bukan strategi, broker, alerts, `request.security`, gambar/label/tabel, atau seluruh v6. Kecuali yang benar-benar dipetakan dan diuji, UI harus memberi diagnostik *belum didukung* alih-alih diam-diam mengabaikan output.
- Target penggunaan browser demo: **WASM harus diuji**, bukan diasumsikan bekerja hanya karena Pinecone ditulis dalam Rust. Jika dependensi/runtime tidak dapat berjalan di `wasm32-unknown-unknown`, simpan panel/editor dan desain bridge terpisah, lalu usulkan jalur worker/server Rust dengan keputusan deployment dan privasi yang eksplisit; jangan mengganti Pinecone dengan PineTS tanpa persetujuan.

## 2. Referensi faktual dan koreksi versi

- [Pinecone](https://github.com/ferranbt/pinecone) adalah runtime Rust berlisensi **MPL-2.0**. Manifest workspace `main` saat brief ini ditulis menyebut `pine-lang` **0.2.6**; README masih mencontohkan `0.1`. Pin versi/commit aktual yang diuji; jangan menyimpulkan API dari README lama. [`ScriptBuilder`, `analyze`, `decode_metadata`, `with_data`, `with_inputs`, `with_request_provider`](https://github.com/ferranbt/pinecone/blob/main/crates/pine/src/lib.rs) merupakan titik awal, tetapi konfirmasi tanda tangan API pada versi yang dipilih.
- **Koreksi penting:** [sumber `PineVersion` di `main`](https://github.com/ferranbt/pinecone/blob/main/crates/pine-core/src/version.rs) telah mengenali **V3/V4/V5/V6**, `LATEST = V6`. README yang menyebut hanya v4/v5 tertinggal. Ini membuktikan *pengenalan versi*, **bukan** kesetaraan fungsi v6 dengan TradingView. Jalankan script v6 yang konkret untuk setiap klaim fitur; unsupported syntax/semantics harus menghasilkan lokasi dan alasan error, tidak di-downgrade secara diam-diam ke v5.
- [Pinecone `Data`/`Ohlcv`](https://github.com/ferranbt/pinecone/blob/main/crates/pine-core/src/bar.rs): bar tertua ke terbaru, waktu UNIX **milidetik**, OHLCV, indeks dan flag barstate. `Data::from_ohlcv` menandai seluruh bar sebagai history/confirmed; **jangan gunakan default tersebut untuk bar forming/live** tanpa menguji dan memasok flag yang benar. `with_syminfo`/`with_timeframe` harus mencerminkan instrument dan timeframe chart, bukan nilai palsu.
- [Pinecone `RunResult`](https://github.com/ferranbt/pinecone/blob/main/crates/pine/src/run.rs) menyusun nilai plot menurut **judul** ke `BTreeMap` dan `None` saat `na`, tetapi tidak mencakup semua warna per bar, urutan deklarasi, drawables, atau metadata gaya yang dibutuhkan chart. Jangan jadikan urutan alfabet `BTreeMap` sebagai indeks plot tetap. Audit [`PineOutput`/`PlotOutput`/`InputOutput`](https://github.com/ferranbt/pinecone/blob/main/crates/pine-core/src/output.rs) dan output **per bar**; tentukan identitas output yang stabil (mis. indeks deklarasi + judul) dan bagaimana metadata `plot()` yang dinamis disimpan.
- [Vela-pinets](https://github.com/LuxAlgo/Vela-pinets) adalah **referensi arsitektur/perilaku v5/v6**, bukan dependensi tugas ini. Pelajari pemisahan engine lewat port, worker untuk beban berat, metadata input/props, per-bar plot/warna/drawing, dan penanganan error. Runtime-nya PineTS/TypeScript dan dependensinya AGPL-3.0; **jangan impor, tempel, atau transliterasi kode** ke bridge MPL/Rust. Vela core dan addon adalah produk berbeda; dukungan fitur di Vela-pinets tidak otomatis ada di Pinecone.
- Pine Script® adalah merek TradingView; jangan menyiratkan kompatibilitas/afiliasi resmi. Lakukan review lisensi dan NOTICE saat mendistribusikan Pinecone atau modifikasinya (MPL-2.0), termasuk bundling WASM; catat versi, lisensi, sumber, dan kewajiban distribusi. Ini bukan nasihat hukum final.

## 3. Graph CBM dan peta source Oracly

Ikuti `.cursor/rules/codebase-memory.mdc` untuk `root-egui-charts`: `search_graph`/`get_architecture` **sebelum** inspeksi source; `trace_path` arah **inbound** sebelum menyunting setiap fungsi; `check_index_coverage` sebelum mengutip berkas; baca source aktual dan diff lokal karena graph dapat usang. Pada penyusunan brief, jalur editor/chart/contoh di bawah berstatus `metadata_match` (best effort); status berubah jika file diedit. Cek ulang sebelum coding. Perubahan dialog settings yang belum dikomit tidak boleh tertimpa pekerjaan Pine.

- `src/ui/study_editor.rs`: **sudah ada** editor generik berisi title/text, Open/Save/Apply request, diagnostik severity + byte span, reveal span, status berhasil/gagal. Belum ada parser atau compiler di komponen ini. Gunakan/tingkatkan seperlunya; jangan menduplikasi editor kedua. Atur fokus, tab, status unsaved, tombol Run, Logs yang bisa dilipat, layout sempit; pertahankan kesepakatan host-owned files/diagnostics. Untuk editor kode lanjutan (syntax highlight, line numbers, autocomplete), rencanakan enhancement tersendiri; versi pertama boleh memakai `egui::TextEdit::code_editor()` yang tersedia.
- `examples/demo/controller.rs`: host demo punya `show_side_panel` dan `egui::Panel::right("detail_panel").resizable(true).min_size(240.0)`; panel kanan digunakan untuk watchlist, object tree, dsb. Tempatkan editor sebagai **pilihan panel** yang terintegrasi navigasi dan pengukuran, bukan modal baru. Jangan mengambil alih `detail_panel` sehingga panel lain rusak; penempatan yang dipilih harus mempertahankan chart ketika editor dibuka. Hubungkan action editor ke host demo yang memiliki `Chart` dan dokumen. `terminal/src/trading.rs` sudah menampilkan `StudyEditor` pada **bottom dock** dan meneruskan `Action::StudyEditor`, tetapi belum menjalankan Pine; pertahankan integrasi ini, jangan paksa terminal desktop menjadi panel kanan dalam tahap pertama.
- `examples/scripting.rs`: hanya contoh bahasa host `close - close[N]`, **bukan runtime Pine**. Cocok sebagai smoke-test pola `CustomIndicator`, warm-up, validasi dan penggantian study, bukan bukti dukungan scripting production.
- `src/studies/custom.rs`: `CustomIndicator` menerima kalkulasi sinkron `Fn(&[Bar]) -> Vec<IndicatorValue> + Send + Sync` atau `with_inputs(...)` untuk input yang divalidasi; menyediakan line count/names, overlay, plot type, fills dan warna per bar. `src/studies/indicator_trait.rs`: `Indicator: Send`; `src/studies/values.rs`: output per bar, `None`/NaN menjadi gap. Interpreter Pinecone menggunakan state single-use dan `Rc` dalam runtime; **jangan meletakkan `Script`/interpreter yang bukan `Send` di `Indicator` atau memalsukan `unsafe impl Send`**. Pilih boundary yang terbukti aman: worker/host memproses snapshot dan mengirim data hasil yang owned + `Send`, atau closure hanya menangkap source/input/data owned dan membuat interpreter lokal pada setiap perhitungan bila performanya terukur. Rancang cara melaporkan error runtime; closure `CustomIndicator` sendiri tidak mengembalikan `Result`.
- `src/model/bar/bar.rs`: `Bar.time: DateTime<Utc>`, OHLCV `f64`; `src/widget/series.rs::Chart::bars(SeriesId::MAIN)` menyediakan bar chart dan `Chart::add_indicator` **langsung menghitung** study; `try_add_indicator` menangani batas study. Preflight compile **dan run** sebelum `remove_series`/`add_indicator`; pelajari cara menjaga identity/history/penempatan saat mengganti script lama. `src/widget/history.rs` menyediakan batas satu user action; tes bahwa gagal tidak menambah undo step/dead legend row.
- `src/widget/studies_data.rs` dan `src/studies/data.rs` adalah kontrak data multi-symbol/timeframe (host resolves histories, tidak mengganti data hilang dengan chart price). `request.security` tidak masuk MVP; gunakan seam ini di fase lanjutan, bukan network fetch langsung di runtime. `src/strategies/backtest.rs` adalah jalur strategi berbeda; integrasi `strategy()` Pine jangan diklaim selesai hanya karena indikator plot berhasil.
- `Cargo.toml` dan `examples/demo/Cargo.toml`: crate demo adalah workspace tersendiri; jangan menambah dependensi Pinecone ke semua feature/crate bila hanya spike host yang memerlukannya. Catat efek pada ukuran bundle WASM dan waktu build `wasm-release` (LTO fat).

## 4. UI: editor kanan mengikuti pola yang benar-benar diamati

- Tambah entry **OpineRust** (tooltip/label lengkap **OpineRust Editor**) ke navigasi panel host demo yang sesuai. Klik menampilkan editor kanan; klik lagi/Close menyembunyikan panel tanpa menghapus teks belum disimpan. Default desktop lebar sekitar 480–520 px dengan rentang resize praktis dan batas minimum untuk chart; penanganan lebar layar kecil harus jelas. Tidak boleh horizontal overflow atau tombol header tertutup. Panel OpineRust tidak boleh salah teridentifikasi sebagai dialog pengaturan study.
- Header: identitas panel **OpineRust** dan judul dokumen (contoh “My script”), **Run** sebagai aksi primer, Save/Open bila host menyediakannya, indikator perubahan belum disimpan, close dan pilihan maximize bila berguna. Di badan: editor multiline selebar panel, tidak scroll seluruh chart; di bawah: Logs/diagnostik bisa dilipat dengan jumlah error/warning dan status runtime/version yang **berdasarkan hasil yang benar**. Pesan status pengguna misalnya “OpineRust: script diterapkan” / “OpineRust: script gagal”, bukan “Pinecone editor”. Klik diagnostik memilih baris/byte span lewat `StudyEditor::reveal`. Keyboard: mengetik tidak memicu shortcut chart, Ctrl/Cmd+Enter untuk Run hanya jika diputuskan dan diuji, Escape dari popup tidak menutup panel secara tak sengaja.
- Pertahankan source mentah saat gagal; jangan hapus indicator lama atau menyatakan Applied sampai stage terakhir berhasil. Disable Run hanya saat pekerjaan sedang berjalan; cegah hasil job lama menimpa job baru melalui generation/token ketika pengguna cepat mengubah code, symbol atau timeframe. Kalau komputasi sinkron panjang membekukan repaint, tandai spike gagal dan pindahkan runtime off-thread/off-main-thread sesuai kemampuan native/WASM; jangan mengklaim UI responsif berdasarkan script pendek saja.
- Pada tahap UI saja, tombol Run harus jelas menyatakan engine belum siap bila bridge belum selesai. Kode editor boleh mempunyai contoh `//@version=5` yang terbukti jalan; contoh v6 **hanya** dipasang setelah lulus tes nyata untuk fitur yang digunakannya.

## 5. Kontrak bridge Rust yang perlu dibuktikan

**Fase awal: `indicator(...)` dengan dua `plot(...)`, v5 dan satu script v6 ekuivalen yang benar-benar lolos.** Bentuk paket data konseptual (bukan signature wajib): source + input overrides + identitas simbol/timeframe/instrument + OHLCV oldest-first + id/generation → compile/execute result berupa status, diagnostik terstruktur, metadata deklarasi, daftar plot dalam urutan tetap, nilai per bar termasuk gap `na`, warna/gaya yang benar-benar dipetakan, dan daftar fitur yang ditolak. Pastikan kepemilikan dan thread boundary eksplisit.

- Input OHLCV: konversi `Bar.time` ke UNIX milidetik tanpa overflow, pertahankan high/low/open/close/volume, urutan waktu, jumlah bar dan timestamp; jangan kirim whitespace/invalid non-finite seolah bar valid. Tentukan kebijakan chart bar terakhir sedang forming, replay, dan perubahan simbol/timeframe; barstate tidak boleh salah. `Pinecone::Data` harus memakai metadata instrument/chart yang nyata atau menyatakan field `syminfo.*` belum didukung bila metadata tidak lengkap. Tidak ada hidden lookahead pada HTF di tahap berikutnya.
- Eksekusi: tentukan `pine-lang` versi/commit terpin. Uji `analyze`/diagnostics, `decode_metadata`/input, `ScriptBuilder::with_data(...)`, `compile`, lalu `run`; amati kebutuhan data untuk compile (jangan klaim compile tanpa data bila API tidak mendukung). Hasil eksekusi harus dibandingkan dengan fixture angka yang diketahui. Audit apakah `run()`/`run_fn` memberi identitas plot deklarasi, warna per bar, style, `overlay`, `input.*`; bila hanya `RunResult` tersedia, **jangan** diam-diam menghilangkan warna atau mengganti urutan plot berdasarkan judul. Batasi scope MVP secara eksplisit jika warna dinamis/fill belum bisa dipetakan.
- Output: urutan bar dan plot stabil, `na`→`IndicatorValue::None`/NaN tanpa menyambung garis melewati gap; `IndicatorValue::Multiple` untuk dua line, `line_count`/`line_names` cocok, `is_overlay` mengikuti deklarasi (atau penempatan host yang sah), warna dasar/warna per bar tidak tertukar. Jangan menjanjikan drawing, bgcolor, fill atau strategy marker hanya karena output Pinecone memiliki tipenya; tiap tipe perlu adaptor render/test tersendiri. Status Error dapat membawa lokasi (lexer/parser) atau diagnostic sema; ubah ke byte span yang valid UTF-8; runtime error tanpa posisi diberi pesan di Logs, bukan lokasi palsu.
- Apply atomik: kalkulasi kandidat **sebelum** chart lama disentuh. Bila gagal di lex/parse/sema/runtime, jumlah study, `SeriesId`, pane, tampilan, input/palette, history/undo dan source editor tetap seperti semula. Bila sukses, tambah/replace dalam **satu user action**; untuk versi pertama boleh memilih “Add new” saja bila replace tidak dapat menjaga id/penempatan—UI harus menamai aksi dengan jujur dan tes terhadap duplikasi. Jangan menggunakan urutan `remove_series` lalu `add_indicator` tanpa strategi rollback ketika proses tambah menghitung/menolak kandidat.
- Perubahan input, bar live, chart symbol/timeframe, replay, dan resize: definisikan invalidasi dan cache. MVP boleh melakukan full replay setelah Run dan pada update data bila beban dibatasi, namun ukur CPU/memori untuk sejarah panjang; pastikan tidak ada interpreter state lama bocor ketika script diulang. Sebelum produksi, buat rencana incremental update/bar forming dan cancellation; jangan lakukan full replay pada tiap repaint egui tanpa batas.
- `request.security` dan library imports ditunda hingga host punya resolver bar history/library yang jelas (termasuk kegagalan unavailable data dan siklus); begitu juga alerts, tables, drawings dan strategi. Saat script memakainya, terbitkan pesan **fitur belum didukung** yang spesifik; jangan tampilkan plot kosong sebagai sukses.

## 6. Fase v6, matriks kapabilitas dan perbandingan referensi

- Simpan **matriks perilaku** per fitur pada laporan DeepSeek: script fixture minimal, target v5/v6, hasil Pinecone (compile/run/output), hasil referensi yang dapat dibandingkan, status `supported` / `partial` / `unsupported`, alasan, test native dan WASM. Pengakuan `PineVersion::V6` saja = *version marker dikenali*, bukan “Pine v6 lengkap”. Jangan mengklaim cocok dengan Vela hanya dari teks README; [Vela-pinets](https://github.com/LuxAlgo/Vela-pinets) dapat dipelajari untuk kontrak engine/worker/props/trades tetapi bukan oracle mutlak per hitungan tanpa fixture.
- Urutan peningkatan setelah MVP: (a) input `int`/`float`/`bool`/`source`/`color`, nilai default dan validation; (b) styling, warna dinamis, fill, plot mode dan gap; (c) perubahan candle live dan `barstate`; (d) `request.security`/MTF/host data; (e) deklarasi v6 yang semantik atau builtinnya berbeda; (f) drawings/tables/alerts; (g) strategi/broker/report. Setiap gelombang menambah fixture regresi v5+v6, error negasi, dan uji native+WASM sebelum status di UI dinaikkan.
- Kalau script `//@version=6` menggunakan subset yang lulus, **boleh** berjalan dan ditandai “v6 subset didukung”; jika meminta fitur belum ada, tolak dengan error spesifik, **jangan menurunkan versi secara diam-diam**. Untuk script tanpa anotasi, pilih kebijakan default yang jelas; Pinecone `LATEST=V6` tetapi dokumentasinya sendiri menyebut Pine tradisional mengasumsikan v1, sehingga pilihan host harus eksplisit dan diuji.

## 7. Tahapan implementasi dan gerbang penerimaan DeepSeek

1. **Baseline:** CBM graph/callers, `git status`/diff, baca source, jalankan tes editor/custom study/host yang ada. Review kompatibilitas lisensi dan apakah Pinecone `0.2.6` (atau commit terpin) membangun native/WASM. Catat fakta API yang berbeda dari brief.
2. **Spike runtime terisolasi:** konversi 20–100 bar fixture ke `pine_core::Data`, jalankan script v5 dua plot dengan warm-up/`na` dan nama/warna; uji satu script v6 ekuivalen, script invalid, dan time conversion. Verifikasi output per bar dan metadata; ukur waktu/memori. Tentukan boundary `Send`/`Rc` tanpa unsafe. Jika gagal di native atau WASM, hentikan klaim integrasi penuh dan laporkan blocker + keputusan alternatif sebelum menyentuh UI production.
3. **Adaptor chart:** peta output ke study yang tampil di overlay/pane, bukti plot count/nama/gap/warna dan id stabil dalam scope yang didukung. Uji atomic Run sukses/gagal, satu user action, stale generation dan tidak ada redraw membeku. Jangan ganggu built-in 201 study/settings yang sedang diubah di working tree.
4. **Panel editor OpineRust:** integrasikan `StudyEditor` di kanan demo dengan entry navigasi **OpineRust**, resize, close, Run, Logs, dan diagnostik berlabel produk yang konsisten; dokumentasikan hubungan dengan terminal bottom dock yang sudah ada. Uji keyboard, fokus, diagnostics reveal, unsaved changes, light/dark, responsivitas viewport ~1440×900, 1024×768, 640×640, 360×640. Klik Run berulang saat kerja async, ubah symbol/timeframe dan pastikan hasil lama tidak menang.
5. **Uji end-to-end & visual:** script dua plot di chart, satu script error menjaga study lama, satu script v6 subset lolos dan satu unsupported v6 ditolak jelas; screenshot editor terbuka/tertutup, Logs error, overlay dan pane. Jalankan formatter, targeted tests, host/demo check, build WASM `examples/demo` melalui Trunk jika ada dependensi web, cek bundle benar-benar baru (mtime/hash). Laporkan perintah dan hasil nyata. Jangan menyebut selesai hanya karena compile atau HTTP 200; lihat chart/editor yang sebenarnya.

**Definition of done untuk milestone pertama:** panel kanan resizable bernama **OpineRust** terlihat bersama chart; tidak ada label produk “Pinecone” atau “Vela” di UI (atribusi dependensi tetap benar di dokumen/lisensi); script Pine v5 dan satu subset v6 dua plot benar-benar jalan pada fixture dan chart; `na`/warm-up, urutan output, judul dan warna yang diklaim sesuai; error tidak menghilangkan study lama; native dan WASM lulus atau blocker dijelaskan tanpa klaim sukses; tidak ada dependensi AGPL yang disalin; daftar kemampuan yang masih belum ada dapat ditemukan dari UI/dokumen. Bila salah satu gerbang belum terpenuhi, tandai milestone **belum selesai** dengan langkah lanjut yang spesifik.
